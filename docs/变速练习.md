# 变速练习原型（0.3.12）

变速功能在 `feature/playback-speed` 开发；0.3.11 偏移修复分支为 `fix/playback-offset`，基于 0.3.10。播放速度与音高一起变化，范围 0.50～1.25 倍，默认 1.00 倍。官谱与自制谱使用同一套已加载数据，不修改 BMS、音频或预设文件格式。

## 操作

1. 启用练习并打开谱面，仍以 A=0、B 未设开始，不自动循环。
2. 点击 `Pause for speed`，停止旧循环并进入游戏原生暂停。
3. 在 `Speed (x)` 输入倍率，如 `0.75`，点击 `Apply speed`。此时保持暂停。
4. 点击 `Resume marking` 继续选段；或填好 A/B 后按 F9，从选段提前位置开始。
5. 每轮循环保持倍率。再次改速度时重复暂停、Apply；输入草稿在点击 Apply 前不生效。

也可在选曲界面先设置并 Apply，再启用练习、进入谱面。恢复 1.00 倍同样暂停后 Apply；退出练习谱面或出错会恢复修改前的音频与 Unity 时间设置。

倍率只在当前游戏进程中保留，不自动写盘，不添加到预设 JSON。选择预设仍只填入区间并停止旧循环，由 F9 开始。

## 时间和判定

A、B、Lead-in 继续表示原歌曲秒数。例如 A=60、B=70，在 0.50 倍时仍练第 60～70 秒，实际播放约 20 秒；提前 3 个歌曲秒实际约 6 秒。采样位置按原音频坐标计算，不把 A/B 再乘或除倍率。

游戏设置里的校准偏移继续表示实际时间，不随速度被拉长或缩短。例如 0.079 秒在 0.50 倍时换算为 0.0395 个歌曲秒，实际仍约 79 毫秒；1.00 倍保持原表现。无需为慢速另改校准设置。谱面自身的音频延迟属于歌曲坐标，保持原值。

提前段保护同样使用歌曲时间：例如提前 3 秒在半速下保护约 6 个实际秒，仍在歌曲 A 点结束；保护期间暂停不会消耗剩余时间。

保留谱面时间下的原判定窗口，慢速时实际时间容错自然变宽。练习期间仍禁用 Fever，本次进程的成绩保存／上传持续阻断，正常记分须退出并重启游戏。

## 实现与限制

- BGM 使用 `AudioSource.pitch`，降低速度也降低音高。
- 只映射当前 `GameGlobal.stopwatch` 实例的 ElapsedTicks 返回值，其他 Stopwatch 不受影响。原生 ElapsedMilliseconds／Elapsed 调用该 getter，三个歌曲时间入口保持同源。
- Spine 无参 `SkeletonAnimation.Update()` 通过 `MDEx.Timer.GlobalTimer.deltaTime` 使用独立墙钟，活动练习谱面将该返回值同倍率缩放一次；暂停／菜单跳过。显式 `Update(float)`、组件和轨道自身速度保持游戏原逻辑，避免重复缩放。
- 在原生 `StageBattleComponent.get_getMusicOffset` 的音频采样位置中，仅校准项按倍率换算，不改偏好、谱面 delay 或音符判定时间。首次接管／改倍率同步音频，刷新回跳偏移缓存；暂停恢复仍经该原生入口，退出时恢复原速校准。
- 原 Stopwatch 的 Start/Stop 排除暂停时长；回跳重设原生与变速时钟锚点，避免逐帧写时钟或重复乘倍率。
- timeScale 与 fixedDeltaTime 同比例配合；暂停菜单恢复原速，Resume 后重新应用。已有音高或全局时间变更时拒绝叠加。
- 不含保音高、运行中实时调速、自动升速或命中音效统一变调。角色、粒子、补间及特殊场景仍需实际谱面验证，尤其是使用非缩放时间的效果。

日志新增 `speed_attached`、`speed_selected`、`speed_restored`、`speed_error`、`speed_calibration`。sample 记录 speed、pitch、unityScale、rawWatchTicks、unityDelta、animationDelta、calibration 和 effectiveCalibration，便于比较歌曲、动画及校准项。日志每次启动覆盖，报告问题前先保存。

## 用户验证重点

保留自己的校准设置，先比较同一区间的 1.00／0.50／0.70 倍，观察 early／late 是否仍有系统偏向；暂停后改倍率、恢复选段并用 F9 回跳，确认校准表现不发生额外变化。让包含齿轮、长条、连打的区间循环多轮，观察漂移、长条动效及角色姿态。再试暂停恢复、F7 重设 A、F9 缺参暂停、预设读取、0.50／1.25／1.00 倍切换和退出后选曲音乐恢复。

本版仅完成离线回归和静态审计，游戏内效果由用户验证。详见 [0.3.12 验证](0.3.12验证.md)。
