# 区间预设（0.3.8）

开启练习并打开谱面后，面板下方 `Saved ranges (local JSON)` 加载预设。初始 A=0、B 留空，读取列表不会开始循环；普通游玩未启用练习时不计算预设指纹。

## 操作

1. 设置 A、B 和 Lead-in 后，点击 `Save new` 保存新预设。无需停止正在运行的循环，也不会因为保存操作启动循环。
2. 点击 `Pause to edit name` 使用游戏原生暂停；此时 Name 输入框可编辑，支持中文，名称长度 1～64 个字符，不能含换行等控制字符。
3. 选择当前谱面版本的预设，会填入 A/B/Lead-in，停止旧循环并清除待执行回跳。保持当前播放或暂停状态，不自动跳转，按 F9 开始。
4. 选择已有预设后，修改参数或名称，再点击 `Update` 更新。修改 Name 后点击 `Save new` 则另外保存一份。
5. `Delete` 需要再点一次 `Confirm delete`，改变选择会取消确认。删除不会清空面板参数。
6. 用 `Previous`、`Next` 翻页，滚轮可滚动预设区域。`Refresh` 重新读取手动导入或编辑的文件。

参数必须完整，A≥0、B≥A+1 秒、提前时间≥0，B 距音频结尾至少 0.25 秒；A 也须满足现有回跳边界。按整数毫秒保存，加载时仍以秒显示，最多三位小数。这不改变游戏的判定精度。

## 文件与匹配

存储位置为游戏目录 `UserData/MuseDashPracticePrototype/presets`。一张谱面的一种难度对应一份 `<记录UUID>.json`，文件包含多个有独立 UUID 的命名预设。手动导入可能产生同谱面的多份文件；保存新预设前先选择目标文件中的一项即可明确保存位置。

文件格式使用 `schemaVersion: 1`，记录：

- 谱面曲名、作者、难度、音频时长，以及 `fingerprintVersion` 和 SHA-256 指纹。
- 最近的曲目 UID 仅作说明，不参与匹配，避免 CustomAlbums 重新编号后关联到别的谱面。
- 每个预设的 `id`、`name`、`aMs`、`bMs`、`leadInMs` 和 UTC 更新时间。

指纹来自加载后的原生音符判定时间、物件 UID、轨道、长度和长条起止类型，并包含音频时长；不包含生成顺序编号、角色速度、物件出现时间、击打状态和实例地址。按稳定顺序及固定数字格式编码。官谱与自制谱共用这一方式。

匹配同时要求曲名、作者、难度和指纹一致。谱面或转换规则更新后可能形成新的版本；指纹不是音频内容哈希，同长度音频被替换时仍需自行核对实际时间对应关系。

## 旧版本复制

同曲名、作者和难度但指纹不同的预设显示 `[other revision]`。点击只供查看，不填入参数；按 `Copy here` 后核对提示，再按 `Confirm copy`。有效区间会复制到当前谱面版本，原文件不变；新复制项会填入参数，但仍由 F9 开始。

如果旧区间超出当前歌曲长度，复制会被拒绝。若当前版本存在多份导入文件，先选择一个当前版本预设以指定目标文件，再选择旧版本项并复制。曲名或作者也改动时不会猜测关联，可备份后手动调整导入文件的元数据，再 Refresh 核对。

## 备份、分享和恢复

只在新建、更新、删除或确认复制时写盘。写入先完整生成同目录临时文件并落盘，再原子替换主文件，上一份保存为 `.json.bak`。删除最后一项时保留空 JSON，避免备份被误当作当前数据重新出现。

主文件缺失、损坏或校验失败时，若 `.bak` 有效，会以 `[backup]` 只读加载并记录警告；主文件和备份都保留。可 `Save new`，或 `Copy here` 并确认保存成可写记录。若主文件只是被其他程序暂时占用，关闭占用后 Refresh 即可。未知 schema 或指纹版本不降级覆盖，错误文件、超大文件不会阻止其他有效预设读取。

分享时复制整份 JSON，保持 UUID 文件名与文件内 `id` 一致，放入接收方同一目录后 Refresh。遇到同名文件先备份，不直接覆盖；不同谱面版本仍走确认复制。不要把个人预设放入模组源码或发布包。

可在关闭游戏后，先另存损坏文件，再用 `.bak` 的内容恢复对应 `.json`；不要在排查前删除原始文件。本版本不会把自制谱加载资源、成绩和存档写进预设。
