# 安装说明

## 环境

当前发布版针对 Windows x64、Muse Dash 6.7.0、Unity 2019.4.41f1、MelonLoader 0.7.0。游戏安装目录应包含 `MuseDash.exe`、`GameAssembly.dll` 和 `Mods`。支持官谱与自制谱；自制谱仍需原有自制谱加载模组，本项目不代替它。

本仓库附带练习模组 DLL，不附带游戏或 MelonLoader 文件。如果游戏尚未安装 MelonLoader，先通过其 [0.7.0 官方发布页](https://github.com/LavaGang/MelonLoader/releases/tag/v0.7.0)准备对应版本，再启动一次游戏完成初始化并退出。现有环境已经安装，无需重复操作。构建还需要 MelonLoader 生成的 `MelonLoader/Il2CppAssemblies`。

## 脚本安装

1. 完全退出游戏。
2. 在本仓库根目录打开 PowerShell。
3. 执行命令，传入包含 `MuseDash.exe` 的文件夹，不要传 `Mods` 文件夹：

```powershell
.\scripts\Install.ps1 -GameRoot 'D:\SteamLibrary\steamapps\common\Muse Dash'
```

本机目前的实际路径可使用：

```powershell
.\scripts\Install.ps1 -GameRoot 'D:\Lilywhite\Steam\steamapps\common\Muse Dash'
```

脚本默认安装 `releases/0.3.9/MuseDashPracticePrototype.dll`。已有相同 DLL 时跳过；不同版本先备份到游戏目录 `UserData/MuseDashPracticeBackups/时间戳`，再替换 `Mods/MuseDashPracticePrototype.dll`。只操作本练习模组，不更新其他模组或 MelonLoader。添加 `-WhatIf` 可以预览操作。脚本发现游戏指纹不一致时会停止，请先核对升级后的兼容性。

若 PowerShell 提示此脚本被执行策略阻止，可仅对这一次进程运行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\Install.ps1 -GameRoot 'D:\SteamLibrary\steamapps\common\Muse Dash'
```

安装后正常启动游戏，在 MelonLoader 日志中确认 `MuseDashPracticePrototype` 0.3.9 已加载。DLL 更新后需重启游戏一次；练习中的每轮循环优先使用场景内回跳。使用方法见 [使用说明](使用说明.md)。

## 手动安装

关闭游戏，先备份 `Mods` 中已有的 `MuseDashPracticePrototype.dll` 到 `Mods` 以外，再复制仓库 `releases/0.3.9/MuseDashPracticePrototype.dll` 到游戏 `Mods` 目录。只保留一个启用的练习 DLL，不要把整个仓库或 `src` 放进 `Mods`。

发布 DLL 的 SHA-256：

```text
EC1256304F463EB28995E830EC961EA122F188C2583DEBA9D0B924DBBC517CF8
```

可用 `Get-FileHash -Algorithm SHA256 '完整DLL路径'` 检查。

## 禁用与回退

退出游戏后执行：

```powershell
.\scripts\Disable.ps1 -GameRoot 'D:\SteamLibrary\steamapps\common\Muse Dash'
```

它将练习 DLL 改名为 `.dll.disabled`，不删除文件。恢复时将后缀改回 `.dll`，确保没有重名的启用 DLL。

回退到安装脚本保存的版本：关闭游戏，将 `UserData/MuseDashPracticeBackups/对应时间戳/MuseDashPracticePrototype.dll` 复制回 `Mods`，覆盖当前练习 DLL。原工作区旧备份及其恢复脚本也保留原位，不与本脚本的新备份混淆。

回退 DLL 不会删除区间预设；0.3.7 会忽略新版本的 `presets` 文件夹。备份、分享和恢复预设 JSON 的方法见 [区间预设](区间预设.md)。

也可从 Git 标签取出历史 DLL，而不切换当前源码：

```powershell
git archive --format=zip --output=previous-0.3.6.zip v0.3.6 MuseDashPracticePrototype.dll
```

解压后先确认版本，再手动安装。不要使用 PowerShell 的 `git show ... > file.dll` 导出二进制，旧版 PowerShell 的文本重定向可能损坏 DLL。

## 从源码编译

需要 .NET SDK 6（迁移验证使用 6.0.424）、已初始化的 MelonLoader 0.7.0 和本机游戏程序集。

```powershell
.\scripts\Build.ps1 -GameRoot 'D:\SteamLibrary\steamapps\common\Muse Dash'
.\scripts\Test.ps1 -GameRoot 'D:\SteamLibrary\steamapps\common\Muse Dash'
```

新 DLL 位于 `artifacts/mod/MuseDashPracticePrototype.dll`；`releases` 中的原发布文件不会被覆盖。检查通过后，安装自己编译的 DLL：

```powershell
.\scripts\Install.ps1 -GameRoot 'D:\SteamLibrary\steamapps\common\Muse Dash' -DllPath '.\artifacts\mod\MuseDashPracticePrototype.dll'
```

源码路径、构建工具与调试符号会影响重新编译的 DLL 哈希，重新编译产物不要求等于原发布哈希。没有 .NET SDK 只影响编译，不影响手动安装现成 DLL。

## 常见检查

- 没看到面板：按 F6，确认 MelonLoader 已加载且 `Mods` 中没有多个练习 DLL。
- 构建缺少引用：确认已启动过安装 MelonLoader 的游戏，检查 `MelonLoader/Il2CppAssemblies/Assembly-CSharp.dll`。
- 原生静态审计缺少 dummy 程序集：检查 `MelonLoader/Dependencies/Il2CppAssemblyGenerator/Cpp2IL/cpp2il_out/Assembly-CSharp.dll`。这是审计依赖，不是运行模组需要额外复制的文件。
- 需要日志：游戏目录 `UserData/MuseDashPracticePrototype/diagnostics.ndjson` 每次启动覆盖，排查前先保存有用的日志。

静态检查通过不等于游戏内效果已经验证；游戏内验证由使用者完成。
